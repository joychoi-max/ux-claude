# Mockup Screens

## Overview

굿럭키 v1 하루 루프 7개 화면(S001~S007)의 상세 목업 설계다. `plan.md`가 화면 목록과 흐름을 정한다면, 이 문서는 각 화면의 목적·진입/이탈·레이아웃(ASCII)·UI 영역·카피 톤·상태·반응형·리뷰 질문·확정 기준을 담는다. 화면 ID와 이름은 `plan.md`와 일치한다.

## Global Mockup Assumptions

- **레이아웃:** 모바일 우선 단일 컬럼. 폭 약 390px 기준 카드 스택, 데스크톱에서는 max-width 약 420~480px의 중앙 정렬 모바일 프레임으로 본다(개인 비서 성격).
- **비주얼:** docs/DESIGN.md 토큰 사용 — 페이지 배경 `#F7F9FA`, 카드 `#FFFFFF` + 1px `#DFE1E2` border + 32px radius, in-app CTA는 flat `#FD7E14`(딥 그라데이션은 랜딩 전용·미사용), 본문 `#71767A`, 헤딩 `#1C1D1F`. Pretendard Variable.
- **아이콘:** 기능 UI(체크박스·내비·상태)는 Phosphor Icons. 이모지는 럭키 대화 카피에만, 메시지당 1개(🍀🌅☀️🌙, 성공 시 ✨).
- **모션:** 바텀시트·패널 진입 300ms ease-out, 로딩은 스켈레톤 시머(1.5s), 불안한 스피너 금지.
- **더미 데이터:** 역할 = "회사 일, 강의, 논문". 할 일 후보 = 회사 보고서 마무리 / 오후 강의 준비 / 논문 인터뷰 정리 / (나머지) 메일 회신·일정 정리·자료 조사·운동. 핵심 3개 = 앞 3개. 정보 한 스푼 = AI 트렌드 1줄·관심 종목 1줄.
- **평가 금지(전역):** 완료율·등급·스트릭·빨강 하락 그래프 어디에도 없음. 진행도는 "N/3" 같은 셀 수 있는 언어로만.
- **호칭:** 사용자는 "윤정님", 럭키는 "~해요/~해볼까요" 친근 존댓말.

## Screen S001 - 첫 만남 화면

**Purpose:** 럭키 페르소나 첫 등장 + 로그인 없는 시작. 역할을 한 번 파악해 콜드 스타트를 해소한다.

**Entry Points:**
- 앱 최초 실행(로그인 없이 바로).

**Exit Points:**
- [럭키랑 시작하기] → S002 (빈 칸이어도 통과).

**Primary User Action:** 역할 한 줄 입력 후 [럭키랑 시작하기].

**Secondary Actions:**
- 입력 건너뛰기(빈 칸으로 바로 시작).

**Layout ASCII:**

```text
+--------------------------------------------------+
|                                                  |
|                     🍀                           |
|                                                  |
|   안녕하세요, 저는 럭키예요.                     |
|   오늘부터 아침·낮·저녁                          |
|   하루를 같이 챙길게요.                          |
|                                                  |
|   먼저, 어떤 하루를 보내세요?                    |
|   +------------------------------------------+   |
|   | 예: 회사 일, 강의, 논문…                 |   |
|   +------------------------------------------+   |
|                                                  |
|   [        럭키랑 시작하기        ]              |
|   · 로그인 없이 바로 시작                        |
+--------------------------------------------------+
```

**Key UI Regions:**
- Header: 럭키 시그니처 🍀 + 인사(페르소나 첫 등장).
- Main: 가치 한 줄(아침·낮·저녁 같이) + 역할 입력칸.
- Actions: [럭키랑 시작하기] 단일 primary CTA.
- Supporting Area: "로그인 없이 바로 시작" 안심 보조 문구.

**Content / Copy Notes:**
- 인사는 따뜻하고 짧게. "같이 챙길게요" 동행감.
- 입력 placeholder는 부담 없는 예시. 강요하는 라벨 금지.

**Data / Placeholder Needs:**
- 입력칸 placeholder 텍스트, 럭키 인사 카피.

**States:**
- Default: 빈 입력칸, CTA 활성(빈 칸도 통과 가능).
- Empty: 해당 없음(첫 화면 자체가 진입점).
- Loading: 해당 없음.
- Error: 해당 없음(입력 검증 없음).
- Selected / Active: 입력칸 포커스 시 border `#FD7E14`.

**Responsive Notes:**
- Mobile: 세로 중앙 정렬, 넉넉한 상하 여백.
- Desktop: 중앙 모바일 프레임, 동일 구성.

**Review Questions:**
- [ ] 첫 화면에서 "나를 챙기는 비서"라는 인상이 즉시 오는가?
- [ ] 역할 입력이 부담이 아니라 가벼운 초대로 느껴지는가?
- [ ] "로그인 없이 시작"이 진입 장벽 제거로 잘 읽히는가?

**Acceptance Criteria:**
- [ ] 럭키 인사·가치 한 줄·역할 입력칸·CTA·보조 문구가 한 화면에 담긴다.
- [ ] CTA가 명확하고, 빈 칸 통과 경로가 막히지 않는다.
- [ ] S002로 이어지는 흐름이 설명 가능하다.

**Notes:**

역할 입력은 선택. 입력하면 S002 제안 품질이 올라간다는 점을 카피로 은근히 유도해도 좋다.

## Screen S002 - 할 일 풀어놓기

**Purpose:** 럭키가 역할 기반 후보를 먼저 깔고, 사용자는 고르기/빼기/추가만 — 입력 마찰 최소화.

**Entry Points:**
- S001에서 [럭키랑 시작하기].

**Exit Points:**
- [이걸로 정리해줘] → S003 (최소 1개 선택 시).

**Primary User Action:** 할 일 1개 이상 선택 후 [이걸로 정리해줘].

**Secondary Actions:**
- 후보 빼기(체크 해제), 직접 추가하기.

**Layout ASCII:**

```text
+--------------------------------------------------+
| 🍀 이런 것들 있으실까요?                         |
+--------------------------------------------------+
|  [✓] 회사 보고서 마무리                          |
|  [✓] 오후 강의 준비                              |
|  [ ] 논문 인터뷰 정리                            |
|  [+] 직접 추가하기                               |
|                                                  |
|  (탭해서 고르거나 빼세요)                        |
+--------------------------------------------------+
|              [     이걸로 정리해줘     ]         |
+--------------------------------------------------+
```

**Key UI Regions:**
- Header: 럭키 제안 멘트("이런 것들 있으실까요?").
- Main: 체크 가능한 할 일 후보 리스트 + 직접 추가 행.
- Actions: [이걸로 정리해줘] CTA(선택 0개면 비활성).
- Supporting Area: "탭해서 고르거나 빼세요" 안내 microcopy.

**Content / Copy Notes:**
- 럭키가 먼저 제안하는 톤. "제가 몇 개 깔아둘게요" 류.
- 빈 상태(역할 미입력)에도 빈 화면 대신 럭키가 일반 후보 제안.

**Data / Placeholder Needs:**
- 후보 4~7개 더미, 체크 상태 값, 추가 입력 인라인 필드.

**States:**
- Default: 후보 제안됨(일부 기본 체크 가능).
- Empty: 역할 미입력 → "무엇부터 챙길까요? 제가 몇 개 제안해드릴게요"와 일반 후보.
- Loading: 제안 준비 중 → 스켈레톤 시머 + "잠깐만요, 오늘 거 같이 정리할게요".
- Error: 네트워크 실패 → 토스트(`#FA5252` border-left) + 재시도 CTA.
- Selected / Active: 1개+ 체크 시 CTA `#FD7E14` 활성 / 0개면 ghost 비활성.

**Responsive Notes:**
- Mobile: 풀폭 리스트 행, 큰 탭 타깃.
- Desktop: 동일, 중앙 프레임.

**Review Questions:**
- [ ] 럭키가 먼저 제안하는 방식이 "알아서 챙겨준다"로 느껴지는가?
- [ ] 최소 1개 선택 전진 조건이 막힘 없이 안내되는가?
- [ ] 직접 추가가 후보 고르기와 자연스럽게 섞이는가?

**Acceptance Criteria:**
- [ ] 제안 후보(체크)·직접 추가·CTA가 동작 흐름과 함께 표현된다.
- [ ] 선택/미선택에 따른 CTA 활성/비활성이 구분된다.
- [ ] 빈 상태에서도 럭키가 먼저 제안한다.

**Notes:**

전진 조건(최소 1개)은 PRD Edge Case와 일치. 0개 선택 시 CTA를 막되 압박하지 않는다.

## Screen S003 - 아침 브리핑 카드

**Purpose:** 흩어진 할 일을 핵심 3개 포커스로 압축(목표 순간) + 정보 한 스푼을 보조 위치로.

**Entry Points:**
- S002에서 [이걸로 정리해줘].
- 다음 날 아침 푸시 → 순환 재진입.

**Exit Points:**
- [좋아, 시작하자] → S004(아침 셋업).

**Primary User Action:** 핵심 3개 확인 후 [좋아, 시작하자].

**Secondary Actions:**
- 나머지 할 일 펼치기/접기, 정보 한 스푼 훑기.

**Layout ASCII:**

```text
+--------------------------------------------------+
| 🌅 윤정님, 오늘 이렇게 가요                      |
+--------------------------------------------------+
|  오늘 꼭 이 3개 ⭐                               |
|   1. 회사 보고서 마무리                          |
|   2. 오후 강의 준비                              |
|   3. 논문 인터뷰 정리                            |
|  ----------------------------------------------  |
|  + 나머지 할 일 4개            ▾                 |
|  ----------------------------------------------  |
|  ☕ 한 스푼 · AI/주식                            |
|   · 오늘 AI 트렌드 한 줄                         |
|   · 관심 종목 한 줄                              |
+--------------------------------------------------+
|              [      좋아, 시작하자      ]        |
+--------------------------------------------------+
```

**Key UI Regions:**
- Header: 🌅 시간대 + 럭키 브리핑 멘트.
- Main: 핵심 3개 ⭐ 포커스(가장 강한 위계).
- Supporting Area: 나머지 할 일(접힘 아코디언) + 정보 한 스푼(보조).
- Actions: [좋아, 시작하자] CTA.

**Content / Copy Notes:**
- "오늘 꼭 이 3개"가 시각적으로 압도적. 정보 한 스푼은 포커스를 흐리지 않게.
- 나머지 할 일은 "버린 게 아니라 접어둔" 톤.

**Data / Placeholder Needs:**
- 핵심 3개 항목, 나머지 4개 카운트, 정보 한 스푼 더미 2줄.

**States:**
- Default: 핵심 3개 + 나머지 접힘 + 정보 한 스푼.
- Empty: 해당 없음(S002에서 최소 1개 보장).
- Loading: 카드 진입 시 스켈레톤(선택).
- Error: 해당 없음(데이터는 S002에서 확정).
- Selected / Active: 나머지 할 일 펼침 상태(아코디언 0.2s ease-out).

**Responsive Notes:**
- Mobile: 단일 카드 풀폭, 핵심 3개 큰 타이포.
- Desktop: 중앙 카드, 동일 위계.

**Review Questions:**
- [ ] 핵심 3개가 화면에서 압도적으로 먼저 들어오는가?
- [ ] 정보 한 스푼이 보조로 잘 눌려 있는가? (포커스를 흐리지 않는가)
- [ ] 나머지 할 일 접힘이 자연스럽게 이해되는가?

**Acceptance Criteria:**
- [ ] 핵심 3개 ⭐·나머지(접힘)·정보 한 스푼·CTA가 위계대로 배치된다.
- [ ] "압축됐다"는 목표 순간이 시각적으로 드러난다.
- [ ] S004로 이어지는 흐름이 설명 가능하다.

**Notes:**

이 화면이 제품의 핵심 목표 순간(머리가 가벼워짐). 위계 설계에 가장 공들일 화면.

## Screen S004 - 홈 (오늘의 하루)

**Purpose:** 하루의 홈베이스. 핵심 3개 체크리스트·진행도·럭키 대화창·다음 능동 케어 예고를 한 화면에. 하루 동안 상태가 바뀌며 반복 진입한다.

**Entry Points:**
- S003에서 [좋아, 시작하자](아침 셋업).
- S006 이후(오후 재정렬).
- S007 이후(하루 닫힘).

**Exit Points:**
- 예약 푸시 발송 → S005(낮/저녁).
- [잘 자요, 럭키] → 종료 → 다음 날 S003.

**Primary User Action:** 상태별 — 아침: 알림 수락(기본 ON) / 오후: 다음 할 일 확인 / 저녁: [잘 자요, 럭키].

**Secondary Actions:**
- 핵심 3개 체크/해제, 럭키한테 말하기(대화창), 🔔 알림 시간 변경 진입.

**Layout ASCII:**

```text
[아침 셋업]                    [오후 재정렬]                  [하루 닫힘]
+----------------------------+ +----------------------------+ +----------------------------+
| 🍀 오늘의 하루   🔔 알림 ON| | 🍀 오늘의 하루   🔔 알림 ON| | 🍀 오늘도 잘 굴렀어요 🌙   |
| ⭐ 핵심 3          0/3     | | ⭐ 핵심 3          1/3     | | ⭐ 오늘 핵심        2/3 ✓  |
| [ ] 회사 보고서 마무리     | | [✓] 회사 보고서 마무리     | | --------------------------|
| [ ] 오후 강의 준비         | | [ ] 오후 강의 준비  ← 다음 | | 📋 내일로 넘어간 것        |
| [ ] 논문 인터뷰 정리       | | [ ] 논문 인터뷰 정리       | | [ ] 논문 인터뷰 정리       |
| -------------------------- | | -------------------------- | | --------------------------|
| 럭키: 낮 2시쯤 잘 가고     | | 럭키: 저녁에 오늘 하루     | | 럭키: 내일 아침 8시에      |
|   있나 다시 톡할게요 ☀️    | |   같이 돌아봐요 🌙         | |   다시 깨우러 올게요 🌅    |
| +------------------------+ | | +------------------------+ | | [    잘 자요, 럭키    ]    |
| | 럭키한테 말하기…       | | | | 럭키한테 말하기…       | | |                            |
| +------------------------+ | | +------------------------+ | |                            |
+----------------------------+ +----------------------------+ +----------------------------+
```

**Key UI Regions:**
- Header: 🍀 + 상태별 타이틀 + 🔔 알림 토글/시간 변경 진입.
- Main: 핵심 3개 체크리스트 + 진행도(N/3).
- Supporting Area: 럭키 대화창(다음 케어 예고 멘트) + 입력칸.
- Actions: 상태별 CTA(아침=암묵 ON, 저녁=[잘 자요]).

**Content / Copy Notes:**
- 진행도는 "N/3"로만. 완료율·등급·스트릭 금지.
- 오후 "← 다음" 강조는 한 개만. 저녁은 인정 톤 + 내일 안심.
- 0개 완료 상태에도 "이런 날도 있죠" 다정 톤, 빨강·하락 금지.

**Data / Placeholder Needs:**
- 핵심 3개 항목 + 체크 상태, 진행도 값, 내일로 이월 항목, 럭키 예고 멘트(시간대별).

**States:**
- Default(아침 셋업): 0/3, 낮 점검 예고, 알림 기본 ON.
- 오후 재정렬: 1/3, "← 다음" 강조, 저녁 예고.
- 하루 닫힘: 2/3 ✓, 내일로 넘어간 항목, 내일 아침 예고, [잘 자요].
- Empty: 할 일 없음 → 럭키 먼저 제안("무엇부터 챙길까요?").
- Loading: 스켈레톤 시머(체크리스트 자리).
- Error: 네트워크 토스트 + 재시도.
- Fell-short(0/3): 다정 톤 + 가장 가벼운 다음 한 걸음, `#FFF4E6` 배경.

**Responsive Notes:**
- Mobile: 풀폭 단일 컬럼, 핵심 3개 스크롤 없이 노출.
- Desktop: 중앙 모바일 프레임.

**Review Questions:**
- [ ] 핵심 3개와 다음 케어 예고가 스크롤 없이 한눈에 들어오는가?
- [ ] 진행도가 평가가 아닌 안심으로 읽히는가? (완료율/등급/스트릭 없음)
- [ ] 아침/오후/저녁 3상태가 같은 화면의 자연스러운 변화로 이어지는가?

**Acceptance Criteria:**
- [ ] 핵심 3개 체크리스트·진행도·알림 토글·럭키 대화창·다음 케어 예고가 한 화면에 담긴다.
- [ ] 아침·오후·저녁 3상태가 모두 표현된다.
- [ ] 다음 화면(S005 푸시 또는 다음 날 S003)으로의 순환이 설명 가능하다.

**Notes:**

모든 흐름이 돌아오는 중심 화면. 상태 전환이 곧 하루 루프의 뼈대다.

## Screen S005 - 푸시 알림

**Purpose:** 럭키가 먼저 말 거는 능동 케어 진입(차별점). 낮·저녁 두 시점.

**Entry Points:**
- S004(아침 셋업) 후 낮 2시 예약 발송(낮).
- S004(오후 재정렬) 후 저녁 9시 예약 발송(저녁).

**Exit Points:**
- 낮 알림 탭 → S006.
- 저녁 알림 탭 → S007.
- 무시 → 흐름 통과(부담 없음).

**Primary User Action:** 알림 탭 → 해당 톡 진입.

**Secondary Actions:**
- 무시(아무 행동 없음).

**Layout ASCII:**

```text
[낮 변형]                              [저녁 변형]
+----------------------------------+   +----------------------------------+
| 🍀 럭키 · 지금                   |   | 🍀 럭키 · 지금                   |
| ☀️ 윤정님, 잘 가고 있어요?       |   | 🌙 오늘 하루 고생 많았어요       |
|    아침에 정한 3개, 같이 볼까요  |   |    같이 오늘 마무리해요          |
+----------------------------------+   +----------------------------------+
```

**Key UI Regions:**
- Header: 🍀 럭키 발신 + 타임스탬프.
- Main: 안부형 카피(낮=☀️ 점검, 저녁=🌙 위로) + 핵심 환기.

**Content / Copy Notes:**
- 잔소리·압박 금지. 안부·동행 톤. 무시해도 부담 없음.
- 메시지당 이모지 1개(낮 ☀️ / 저녁 🌙).

**Data / Placeholder Needs:**
- 낮·저녁 각 알림 카피, 타임스탬프 더미.

**States:**
- Default: 해당 없음(알림은 단일 표시 상태).
- 낮 변형: ☀️ "잘 가고 있어요?".
- 저녁 변형: 🌙 "고생 많았어요".
- Loading/Error: 해당 없음(목업은 정적).

**Responsive Notes:**
- Mobile: 시스템 알림/잠금화면 스타일 카드.
- Desktop: 동일 알림 카드 형태로 표현.

**Review Questions:**
- [ ] 카피가 잔소리·압박이 아니라 안부·동행으로 느껴지는가?
- [ ] 무시해도 부담 없다는 톤이 전달되는가?
- [ ] 낮·저녁 변형의 시간대 톤 차이가 분명한가?

**Acceptance Criteria:**
- [ ] 럭키 발신·안부형 카피·핵심 환기가 알림 형태로 표현된다.
- [ ] 낮·저녁 변형이 구분된다.
- [ ] 탭 → S006/S007 진입 흐름이 설명 가능하다.

**Notes:**

목업에서 알림 표현 방식(잠금화면형 vs 앱 내 진입 카드)은 plan.md Open Questions 참고 — 리뷰에서 확정.

## Screen S006 - 낮 점검 톡

**Purpose:** 럭키가 진행을 체크하되 탭 한 번으로 끝, 못 했어도 응원(잔소리 X).

**Entry Points:**
- S005(낮) 알림 탭.

**Exit Points:**
- [응, 다시 달려볼게] → S004(오후 재정렬).
- 무탭도 통과.

**Primary User Action:** 한 거만 탭 → [응, 다시 달려볼게].

**Secondary Actions:**
- 체크 없이 그냥 닫기(통과).

**Layout ASCII:**

```text
+--------------------------------------------------+
| 🍀 오후도 화이팅이에요 ☀️                        |
|    핵심 3개 중 어디까지 왔어요?                  |
|    (한 거만 탭해주세요)                          |
+--------------------------------------------------+
|  [✓] 회사 보고서 마무리                          |
|  [ ] 오후 강의 준비                              |
|  [ ] 논문 인터뷰 정리                            |
+--------------------------------------------------+
| 🍀 1개 했네요! 아직 오후 충분해요.              |
|    다음 거 가볍게 👍                             |
|              [     응, 다시 달려볼게     ]       |
+--------------------------------------------------+
```

**Key UI Regions:**
- Header: 🍀 ☀️ 응원 멘트 + "한 거만 탭" 안내.
- Main: 핵심 3개 체크 칩.
- Supporting Area: 럭키 응원 멘트(진행 반영).
- Actions: [응, 다시 달려볼게] CTA.

**Content / Copy Notes:**
- 체크는 선택, 안 해도 통과. 0개여도 "오후는 아직 충분해요" + 가장 가벼운 다음 한 걸음.
- 빨강·하락·잔소리 금지. 응원 톤만.

**Data / Placeholder Needs:**
- 핵심 3개 칩 + 체크 상태, 진행별 응원 멘트 변형.

**States:**
- Default: 체크 칩 + 응원 멘트.
- 1개+ 완료: "1개 했네요! 아직 오후 충분해요".
- Fell-short(0개): "오후는 아직 충분해요. 제일 가벼운 것 하나만", `#FFF4E6` 배경·`#F76707` 아이콘.
- Loading/Error: 진입 시 스켈레톤(선택) / 네트워크 토스트.

**Responsive Notes:**
- Mobile: 풀폭 톡 시트.
- Desktop: 중앙 프레임 동일.

**Review Questions:**
- [ ] 체크가 "선택"이고 안 해도 통과한다는 게 느껴지는가?
- [ ] 0개 완료에도 죄책감 없이 가장 가벼운 다음 한 걸음만 제시되는가?
- [ ] 30초 안에 끝나는 가벼움이 전달되는가?

**Acceptance Criteria:**
- [ ] 핵심 3개 체크 칩·럭키 응원 멘트·CTA가 표현된다.
- [ ] 1개+/0개 완료 상태가 모두 응원 톤으로 구분된다.
- [ ] S004(오후 재정렬)로의 흐름이 설명 가능하다.

**Notes:**

PRD FR-006·SC-002와 직접 연결. "탭 한 번 또는 무탭 통과"가 핵심 UX.

## Screen S007 - 저녁 마무리 톡

**Purpose:** 한 일 먼저 인정(평가 아닌 격려) → 못 한 일을 탭 한 번으로 안전하게 내일로 이월.

**Entry Points:**
- S005(저녁) 알림 탭.

**Exit Points:**
- [내일로 옮기기] 또는 [오늘은 여기까지] → S004(하루 닫힘).

**Primary User Action:** [내일로 옮기기] 또는 [오늘은 여기까지].

**Secondary Actions:**
- 완료 항목 훑기(인정 확인).

**Layout ASCII:**

```text
+--------------------------------------------------+
| 🍀 오늘 이만큼 했어요 👏                          |
|    2개나 해냈어요, 잘했어요!                     |
+--------------------------------------------------+
|  [✓] 회사 보고서 마무리                          |
|  [✓] 오후 강의 준비                              |
|  ----------------------------------------------  |
|  못 한 건 내일로 넘길까요?                       |
|  [ ] 논문 인터뷰 정리                            |
+--------------------------------------------------+
|              [      내일로 옮기기      ]         |
|              [      오늘은 여기까지     ]         |
+--------------------------------------------------+
```

**Key UI Regions:**
- Header: 🍀 인정 멘트(한 일 먼저, 크게).
- Main: 완료 항목(인정) + 못 한 항목(이월 후보).
- Actions: [내일로 옮기기] primary / [오늘은 여기까지] secondary.

**Content / Copy Notes:**
- 인정이 못 한 일 지적보다 먼저·크게. 이월은 "안전하게 옮김" 톤.
- 0개 완료에도 "이런 날도 있죠" 다정 톤. 전부 완료면 못 한 항목 섹션 생략.

**Data / Placeholder Needs:**
- 완료 항목 목록, 못 한 항목 목록, 인정 멘트 변형(개수별).

**States:**
- Default: 완료 2 + 못 한 1(이월 제안).
- Fell-short(0개 완료): "이런 날도 있죠", 인정 톤 유지, 빨강 금지.
- 전부 완료: 못 한 항목 없음 → 인정만, 이월 섹션 생략.
- Loading/Error: 진입 스켈레톤(선택) / 네트워크 토스트.

**Responsive Notes:**
- Mobile: 풀폭 톡 시트, CTA 2개 세로 스택.
- Desktop: 중앙 프레임 동일.

**Review Questions:**
- [ ] 한 일 인정이 못 한 일 지적보다 먼저·크게 오는가?
- [ ] 이월이 "사라짐"이 아니라 "안전하게 내일로"로 느껴지는가?
- [ ] [오늘은 여기까지]가 죄책감 없는 닫기로 읽히는가?

**Acceptance Criteria:**
- [ ] 완료 항목(인정)·못 한 항목·[내일로 옮기기]·[오늘은 여기까지]가 표현된다.
- [ ] 0개/전부 완료 변형이 다뤄진다.
- [ ] S004(하루 닫힘)로의 흐름이 설명 가능하다.

**Notes:**

PRD FR-008·SC-003과 직접 연결. 이월 항목은 "내일로 옮김" 라벨로 다음 아침 재등장(S003 순환).
