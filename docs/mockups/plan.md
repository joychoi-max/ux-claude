# Mockup Plan

## Overview

굿럭키(Good Lucky) v1의 하루 루프(아침→낮→저녁→다음 아침)를 프론트엔드 목업으로 그리기 위한 화면 계획이다. 코드 구현 전에 어떤 화면을 어떤 순서로 목업하고, 무엇을 리뷰·확정할지 정리한다. 이 문서는 화면 목록과 화면 간 흐름을, `screens.md`는 각 화면의 상세 설계를 담는다.

목업의 목표는 럭키의 핵심 차별점 — **아침·낮·저녁 먼저 말 걸어 페이스를 잡아주는 일관된 페르소나** — 이 화면 위에서 실제로 느껴지는지를 눈으로 확인하는 것이다.

## Source Context

- PRD: 로그인 없는 시작(FR-001), 럭키의 할 일 후보 제안(FR-002), 핵심 3개 압축(FR-003), 3구간 능동 알림(FR-004), 홈 홈베이스(FR-005), 낮 점검(FR-006~007), 저녁 마무리·이월(FR-008~009), 대화형(FR-010), 정보 한 스푼(FR-011), 알림 시간 변경(FR-012). User Scenarios 1~3과 Edge Cases(빈 상태·무응답·0개 완료·이월·네트워크·로딩)를 화면 상태로 반영.
- User Flows: 플로우 1(첫 사용+아침 브리핑) 4단계, 플로우 2(낮 중간 점검) 3단계, 플로우 3(저녁 마무리) 3단계. 화면 인벤토리 7개를 화면 ID로 매핑.
- Additional Context: docs/DESIGN.md — warm orange `#FF8D00`/`#FD7E14` CTA, Pretendard Variable, 카드 32px·버튼 12px radius, 차분한 모션(300ms ease-out), Phosphor Icons, 이모지 제한(🍀🌅☀️🌙✨), 평가 금지(스트릭/완료율/등급 없음), 빈/로딩/오류/이월 상태 카피 가이드.

## Mockup Scope

- 7개 화면(S001~S007)의 기본 상태 목업.
- 흐름상 핵심인 다중 상태: 홈(S004)의 아침 셋업 / 오후 재정렬 / 하루 닫힘 3상태, 푸시 알림(S005)의 낮·저녁 2변형, 할 일 풀어놓기(S002)의 선택/빈 상태, 낮 점검(S006)·저녁 마무리(S007)의 0개 완료(fell-short) 상태.
- 화면 간 전환 흐름이 하루 루프로 순환 연결되는 것까지를 목업으로 확인.
- 더미 데이터(역할: "회사 일·강의·논문", 핵심 3개 샘플 할 일)로 정적 렌더.

## Out of Scope

- 실제 인증·계정(로그인 없이 시작).
- DB 저장·서버 상태 동기화.
- 실제 푸시 발송(텔레그램/카카오 알림톡 연동) — 목업에서는 알림 화면을 정적으로만 표현.
- 정보 한 스푼의 실데이터 소스(AI 트렌드·종목 API) — 더미 한 줄 텍스트.
- 알림 시간 변경 상세 설정 화면 — 토글/진입점만 표시, 설정 모달은 P1.
- 패턴 분석(FR-013)·페이스 시각화(FR-014)·사용자별 리듬(FR-015).

## Screen Flow

```text
[S001 첫 만남 화면]
  -> [S002 할 일 풀어놓기]
      -> [S003 아침 브리핑 카드]
          -> [S004 홈 (오늘의 하루) · 아침 셋업]
              -> (낮) [S005 푸시 알림 · 낮]
                  -> [S006 낮 점검 톡]
                      -> [S004 홈 · 오후 재정렬]
              -> (저녁) [S005 푸시 알림 · 저녁]
                  -> [S007 저녁 마무리 톡]
                      -> [S004 홈 · 하루 닫힘]
                          -> (다음 아침) [S003 아침 브리핑 카드] ... 순환
```

## [x] Screen S001 - 첫 만남 화면

**Purpose:** 럭키 페르소나의 첫 등장과 로그인 없는 시작. 사용자 역할을 한 번 파악해 콜드 스타트를 해소한다.

**User Moment:** 플로우 1 ① — 챙길 게 많아 산만한 채로 앱을 처음 연다.

**Primary Action:** 역할 한 줄 입력 → [럭키랑 시작하기].

**Leads To:** S002.

**States to Mock:** 기본(빈 입력칸), 입력됨(텍스트 있음).

**Review Focus:**
- [ ] 첫 화면에서 "이건 나를 챙기는 비서"라는 인상이 즉시 오는가?
- [ ] 역할 입력이 부담이 아니라 가벼운 초대로 느껴지는가? (건너뛰기 가능성이 보이는가)

**Done When:**
- [ ] 럭키 인사·가치 한 줄·역할 입력칸·CTA·"로그인 없이 시작" 보조 문구가 한 화면에 담긴다.

## [x] Screen S002 - 할 일 풀어놓기

**Purpose:** 럭키가 역할 기반 할 일 후보를 먼저 깔고, 사용자는 고르기/빼기/추가만 해 입력 마찰을 최소화한다.

**User Moment:** 플로우 1 ② — "뭐부터 하지"를 럭키가 먼저 제안으로 받아준다.

**Primary Action:** 할 일 1개 이상 선택 → [이걸로 정리해줘].

**Leads To:** S003.

**States to Mock:** 기본(후보 제안됨), 선택됨(1개+ 체크 → CTA 활성), 미선택(0개 → CTA 비활성), 빈 상태(역할 미입력 시 럭키가 먼저 제안), 로딩(제안 준비 중 스켈레톤).

**Review Focus:**
- [ ] 후보를 럭키가 먼저 제안하는 방식이 "알아서 챙겨준다"로 느껴지는가?
- [ ] 최소 1개 선택 전진 조건이 막힘 없이 자연스럽게 안내되는가?

**Done When:**
- [ ] 제안 후보(체크) · 직접 추가 · [이걸로 정리해줘]가 동작 흐름과 함께 표현되고, 선택/미선택 상태가 구분된다.

## [ ] Screen S003 - 아침 브리핑 카드

**Purpose:** 흩어진 할 일을 핵심 3개 포커스로 압축(제품의 목표 순간) + 정보 한 스푼을 포커스 아래 보조로.

**User Moment:** 플로우 1 ③ — "오 이게 내 하루구나" 하며 머리가 가벼워지는 순간.

**Primary Action:** 핵심 3개 확인 → [좋아, 시작하자].

**Leads To:** S004(아침 셋업).

**States to Mock:** 기본(핵심 3개 + 나머지 접힘), 나머지 펼침(아코디언), 정보 한 스푼 노출.

**Review Focus:**
- [ ] 핵심 3개가 화면에서 압도적으로 먼저 눈에 들어오는가? (정보 한 스푼이 포커스를 흐리지 않는가)
- [ ] 나머지 할 일 접힘이 "버린 게 아니라 잠시 접어둔" 느낌인가?

**Done When:**
- [ ] 핵심 3개 ⭐ · 나머지 할 일(접힘) · 정보 한 스푼(보조) · CTA가 위계대로 배치된다.

## [ ] Screen S004 - 홈 (오늘의 하루)

**Purpose:** 하루의 홈베이스. 핵심 3개 체크리스트·진행도·럭키 대화창·다음 능동 케어 예고를 한 화면에 모은다. 하루 동안 상태가 바뀌며 반복 진입한다.

**User Moment:** 플로우 1 ④(아침 셋업) · 플로우 2 ③(오후 재정렬) · 플로우 3 ③(하루 닫힘) — 모든 흐름이 돌아오는 중심 화면.

**Primary Action:** 상태별 — 아침: 알림 수락(기본 ON) / 오후: 다음 할 일 확인 / 저녁: [잘 자요, 럭키].

**Leads To:** S005(예약 푸시) 또는 종료 → 다음 날 S003.

**States to Mock:** 아침 셋업(0/3, 낮 점검 예고), 오후 재정렬(1/3, "다음" 강조, 저녁 예고), 하루 닫힘(2/3, 내일로 넘어간 항목, 내일 아침 예고), 빈 상태(할 일 없음 → 럭키 먼저 제안), 0개 완료(fell-short, 다정 톤·빨강 금지).

**Review Focus:**
- [ ] 핵심 3개와 다음 능동 케어 예고가 스크롤 없이 한눈에 들어오는가?
- [ ] 진행도가 평가가 아닌 "갈 만하다"는 안심으로 읽히는가? (완료율/등급/스트릭 없음 확인)
- [ ] 세 상태가 같은 화면의 자연스러운 변화로 이어지는가?

**Done When:**
- [ ] 핵심 3개 체크리스트·진행도(N/3)·알림 토글·럭키 대화창·다음 케어 예고가 한 화면에 담기고, 아침/오후/저녁 3상태가 모두 표현된다.

## [ ] Screen S005 - 푸시 알림

**Purpose:** 럭키가 먼저 말 거는 능동 케어 진입(우리 차별점). 낮·저녁 두 시점의 안부형 알림을 표현한다.

**User Moment:** 플로우 2 ①(낮) · 플로우 3 ①(저녁) — 일하다/하루 끝에 럭키 푸시를 받는 순간.

**Primary Action:** 알림 탭 → 해당 톡 진입.

**Leads To:** 낮 → S006, 저녁 → S007.

**States to Mock:** 낮 변형(☀️ "잘 가고 있어요?"), 저녁 변형(🌙 "고생 많았어요").

**Review Focus:**
- [ ] 알림 카피가 잔소리·압박이 아니라 안부·동행으로 느껴지는가?
- [ ] 무시해도 부담 없다는 톤이 전달되는가?

**Done When:**
- [ ] 럭키 발신·안부형 카피·핵심 환기가 알림 형태로 표현되고, 낮·저녁 변형이 구분된다.

## [ ] Screen S006 - 낮 점검 톡

**Purpose:** 럭키가 진행을 체크하되 탭 한 번으로 끝나고, 못 했어도 응원(잔소리 X)하는 낮 중간 점검.

**User Moment:** 플로우 2 ② — "1개 했고 2개 남았네, 아직 갈 만하다"로 찜찜함이 걷히는 순간.

**Primary Action:** 한 거만 탭 → [응, 다시 달려볼게] (무탭도 통과).

**Leads To:** S004(오후 재정렬).

**States to Mock:** 기본(체크 칩 + 응원 멘트), 1개+ 완료(응원 톤), 0개 완료(fell-short — "오후는 아직 충분해요", `#FFF4E6` 배경·`#F76707` 아이콘, 빨강·하락 금지).

**Review Focus:**
- [ ] 체크가 "선택"이고 안 해도 통과한다는 게 느껴지는가? (압박 없음)
- [ ] 0개 완료에도 죄책감 없이 가장 가벼운 다음 한 걸음만 제시되는가?

**Done When:**
- [ ] 핵심 3개 체크 칩·럭키 응원 멘트·CTA가 표현되고, 1개+/0개 완료 상태가 모두 응원 톤으로 구분된다.

## [ ] Screen S007 - 저녁 마무리 톡

**Purpose:** 한 일을 먼저 인정(평가 아닌 격려)하고, 못 한 일을 탭 한 번으로 안전하게 내일로 이월한다.

**User Moment:** 플로우 3 ② — "2개 했고, 1개는 내일로" 깔끔하게 닫히는 순간.

**Primary Action:** [내일로 옮기기] 또는 [오늘은 여기까지].

**Leads To:** S004(하루 닫힘).

**States to Mock:** 기본(완료 항목 인정 + 못 한 항목 이월 제안), 0개 완료(fell-short — "이런 날도 있죠", 다정 톤), 전부 완료(못 한 항목 없음 → 인정만).

**Review Focus:**
- [ ] 한 일 인정이 못 한 일 지적보다 먼저·크게 오는가?
- [ ] 이월이 "사라짐"이 아니라 "안전하게 내일로 옮김"으로 느껴지는가?

**Done When:**
- [ ] 완료 항목(인정)·못 한 항목·[내일로 옮기기]·[오늘은 여기까지]가 표현되고, 0개/전부 완료 변형이 다뤄진다.

## Open Questions

- 정보 한 스푼(S003)의 더미 카피를 어느 수준으로 보여줄지 — 한 줄 텍스트 2개로 충분한가, 아니면 카드형으로 보일지.
- 푸시 알림(S005)을 목업에서 어떻게 표현할지 — 시스템 알림 형태(잠금화면 스타일)로 그릴지, 앱 내 진입 카드로 그릴지.
- 홈(S004)의 럭키 대화창이 v1 목업에서 실제 입력 가능한 형태여야 하는지, 아니면 예고 멘트 표시 위주의 정적 영역인지.
